About this project

This project was a group based project with a focus on agile software development. We set out to design an app that estimates solar energy production for homes and cabins in Norway. The goal was to combine weather data, location, and roof details into actionable insights for users considering solar panels. The app also includes a function that lets you choose different housewares and how much power they will use for off-grid cabins. The app shows the user’s house on a map along with weather conditions that can affect the panels power. During the project we had interviews and user-testing with users who were interested in installing solar panels.

Early process

We began the design process by defining functional and non-functional requirements, then narrowed them down to an MVP focused on core features: address lookup, weather data integration, solar output calculation, and power production estimates. We used Crazy 8s to generate ideas, created wireframes in Figma, and validated early concepts through user interviews. The MVP was developed with Scrumban, using weekly sprints, reviews, and retrospectives. Initial challenges included incomplete API data, which we solved by working with available static datasets. The demo confirmed that the calculations worked but revealed the need for a clearer product direction. Based on feedback, we refined requirements and built a user story: “The user should get an estimate of potential solar energy production for their home or cabin based on location-specific weather data.”

Testing design alternatives

In the next phase, we expanded functionality to include monthly production estimates, cost-benefit analysis, off-grid capacity, and informational content. We iterated on design for the power, economy, and consumption pages, and tested prototypes with users. Insights from testing different design options showed a preference for simpler input, clearer graphs, and better explanations of technical terms.

Based on the feedback from testing different design options, we made improvements to the desgn. To validate improvements, we conducted guerrilla testing with random participants. This confirmed the need for intuitive navigation and contextual guidance. We redesigned the consumption page with explanatory text and clear watt/hour displays, simplified graphs with labels, and made the profile easier to edit. Contextual info icons replaced a separate info page, keeping the interface clean.

During the design process we stumbled upon deadline and technical limitations that influenced design decisions. Because of this we had to make some compromises on both functionality and design. For instance prioritizing core functionality from the case description and most useful functionality for the users. To reach the deadline we chose to drop a functionality comparing effect from solar panels to other energy sources. We also chose to not have a info screen, but instead itegrate info where needed in the app, which the users ended up preffering.

Outcome

Before final delivery, we held a Technical Cleanup Day, reviewing and refactoring the code in rounds to ensure quality and shared ownership. The final product was a functional, user-tested solar estimation app that calculates solar energy production using weather and roof data provides intuitive visualizations of consumption and savings guides users with contextual information and simplified flows

This project gave me more knowledge about working in software teams, especially as a designer, as my main role in the team was design and research. Key takeaways from this project includes the importance of early user involvement, simplifying complexity in both design and input, and maintaining flexibility when APIs or data sources posed challenges.
